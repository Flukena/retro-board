# Script catalog

- `landing-live-check.mjs` — Read-only sticky Public dock/recent-room navigation regression. Seeds ten synthetic recent entries only in isolated browser local storage; checks native scroll-cue navigation, persistent dock during scrolling, unobscured final row/removal, empty state, mobile keyboard viewport and no POST/WebSocket room activity at320/390/430/768/844/1440px inTH/EN/light/dark. Run `node scripts/landing-live-check.mjs <base-url> <SSD output> [chromium|webkit]`; supports localhost and retroroom.party without room writes. Uses global Playwright; all screenshots/reports/browser scratch stay on mounted SSD.

- `check-resource-budget.mjs` — Validate resolved production Compose services share CPU IDs `0,1` and their finite memory limits total at most 3,000,000,000 bytes. Includes inherited relay/tunnel services and the one-shot initializer. Run `node scripts/check-resource-budget.mjs [compose-file]`; requires Docker Compose, reads no `.env` or service env-file values, changes no containers and emits only the resource summary as UTC JSON.

- `test.mjs` — Run every root/nested source/script test with the current Node binary; forwards test-runner CLI flags. Use `npm test -- --test-concurrency=1` for the serial capacity gate.
- `project-files.mjs` — Shared recursive file discovery used by the test runner and architecture/color/token gates; excludes no nested feature tests.

- `pan-live-check.mjs` — Isolated Public pan performance regression with two uploaded raster images, nested zones at fractional coordinates and a large board fixture; checks desktop/mobile retina frame p95 <=50ms while keeping image shadows visible. Chromium also requires <=8 paint events over180 pan frames, guarding compositing for fractional zone edges and the cached grid texture; zoom is also measured against the same frame-time budget. Requires an empty dedicated local Public relay behind Vite/preview on port5188; measure a production build for release timings. Run `PLAYWRIGHT_BROWSERS_PATH=<SSD browsers> node scripts/pan-live-check.mjs http://127.0.0.1:5188 <BaseData output> [webkit|chromium]`. Removes only its own fixture items, retains uploads, and writes captures/traces/browser scratch to the mounted operator SSD. Pass a final `cards` argument after the engine for1,000 valid stickies at12% zoom and Chromium4x CPU slowdown; checks the same frame budget on desktop/mobile. The default `images` fixture retains its image-shadow and paint-count gates. Use `chromium smooth` for the stricter1,000-card/4x CPU check with actual GPU compositing enabled, p95<=18ms and no frame above50ms; it fails if hardware GPU is unavailable and also checks overview hover, zoom-to-edit, Undo/Redo and return to overview. The `sweep` profile additionally zooms12%→100%→12% three times with30 idle frames per direction, retaining the same18ms p95/50ms maximum GPU budgets through gesture release and native-detail hydration; it records both RAF timestamps and callback timing, bounded slow-frame diagnostics and minimap redraws, and checks the persistent card pool. The `pinch` profile (Chromium, 390px only) drives three trusted two-finger CDP touch pinches 12%→48%→12% over the 1,000-card fixture at 4x CPU slowdown and fails if any frame moves against the fingers, p95 exceeds 50ms or raster exceeds 25 tiles per input frame (the per-frame full-board re-raster that held live raster removes). Zoom/pinch samples also report `rasterTasks`/`rasterMs` from the trace. Does not replace physical-device testing.

- `verify-production-backup.sh` — Decrypt a backup into scratch storage and verify its LevelDB documents open.
- `scan-production-images.sh` — Scan source secrets, container configuration and production images with pinned Trivy.
- `decode-scan.mjs` — Count board items the client's remote-board decoder would hide, plus per-room encoded MiB, from a COPY of a LevelDB directory; prints counts and field/type names only, never board content. `node scripts/decode-scan.mjs <leveldb-copy-dir>`.
- `ui-live-check.mjs` — Check landing/board appearances, two-user sync and undo/redo using global Playwright; writes nine screenshots and `report.json` under BaseData. Start the Vite/relay servers as documented in its header, then run `node scripts/ui-live-check.mjs --base-url http://127.0.0.1:5180 --out <BaseData>/<task>/<run>`. Each run creates one board, so raise the relay's per-IP room-create limit (header shows the env) for repeated local runs; use `--strict-console` to fail on console errors or `PLAYWRIGHT_MODULE` to override module resolution.

- `relay-hydration-probe.mjs` — Seed a board with 15,000 item maps/texts, then measure cold LevelDB hydration in a fresh process (heap checkpoints plus GC before sizes, and RSS high-water mark). Requires an existing `RB_PROBE_DIR` on the operator-selected bulk storage; retains database and worker logs there. Run `RB_PROBE_DIR=<BaseData>/<task>/probe node --max-old-space-size=432 scripts/relay-hydration-probe.mjs`. Reports Node/V8 limits, encoded bytes, observed peak heap/RSS, and per-phase memory.

- `public-wall-restore.sh` — Restore one encoded Public Wall snapshot with the public relay stopped. Usage: `scripts/public-wall-restore.sh <public-data-directory> <public-data-directory>/snapshots/wall-<UTC-epoch-ms>.bin`. Refuses unmarked/private directories, external snapshots and a database locked by a running relay. Publishes the snapshot into a new room/document with marker-last creation, then retires the old handle so stale replicas cannot reconnect; public clients re-enter and reload automatically. Production restoration requires owner approval. The `.mjs` companion supplies the CLI; `src/server/public-wall-restore.js` owns validation and recovery.

Switching tools or Escape flushes remaining completed strokes; the toolbar has no Done button; Cancel discards only changes not already saved.
