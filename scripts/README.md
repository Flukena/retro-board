- `live-check-all.mjs` — Sequential live-check runner for the refactor gates (design §7.5). For each manifest entry, in file order, it does five things. It creates `<out-root>/<id>/run-<n>` on a mounted data volume (no fallback, and an existing run dir is refused so the relay never reuses an old db). It checks that every port the run needs is free on `127.0.0.1` and `::1`; a foreign holder is reported as `ENV-SKIP <id>: port <n> in use`, and nothing is killed or reused. It starts the entry's servers (`<name>.log` per server) and runs the check under a hard timeout that kills its whole process group (Playwright starts Chromium in a group of its own and closes it on the check's SIGTERM, within a 5 s grace before SIGKILL). It always stops the servers it started and confirms their ports are free again. It writes `summary.json` (exit code, timeout, PASS/FAIL step counts, first failed step, duration, verdict) plus the check's stdout and stderr. It prints one line per entry and exits non-zero on any regression, ENV-SKIP or interruption; SIGINT, SIGTERM, SIGHUP or SIGALRM (Ctrl-C, or an outer `perl -e 'alarm N; exec @ARGV'` bound) stops the running check and its servers first. Make any outer bound longer than the sum of each selected check's `timeoutSec` plus server start-up (up to 60 s) and the 5 s stop grace, so that the runner's own per-check timeout fires before it. Run `node scripts/live-check-all.mjs --out-root <fresh BaseData dir> [--only id,id] [--attempts n]`, or `--list` to print the ids. `account` also needs `npm run maintainer:build` once. Uses global Playwright through each check; one Chromium at a time.
- `live-check-common.mjs` — The runner's shared pieces, not run directly. It holds the manifest decoder (`parseManifest`, which names the bad entry) and the pure recipes: `portsFor` (vite `5301+i`, relay `1301+i`, oidc `4401+i`, maintainer `1351+i`; the Public relay always on 1235, where Vite proxies), `serverPlan`, `checkCommand` and `checkEnv`. The per-run maintainer key goes only into env, never into argv, a file or a log. It also holds `assertPortsFree` (a TCP connect probe on IPv4 and IPv6 loopback that never signals the holder), `startServers`/`stop()` (detached process groups, readiness on each server's own host), `runWithHardTimeout` (group SIGTERM then SIGKILL, with a `/usr/bin/perl` alarm as backstop; perl is required there, never looked up through PATH) and the verdict helpers `summarizeRun`/`judgeRun`.
- `live-check-manifest.json` — One entry per live check: its script and args (`{base}`, `{out}`), stack (`plain`, or `oidc` with the fake Google; `oidcInCheck` when the check runs the stub itself), Vite host, optional fixed Vite port, Public relay and maintainer flags, extra relay and check env (`{oidcPort}`, `{relayPort}`), timeout and baseline. A baseline is one of `pass`, `known-red`, `env-skip`, `flaky` or `unrun`; `known-red`, `env-skip` and `flaky` also need a `reason`, `known-red` needs a `failingStep` and `flaky` an `observedFailRate`. A run passes only when the check exits 0 and prints no `FAIL <step>` line (fail-closed); a timeout or a non-zero exit fails it even without a FAIL line. A `known-red` failure matches only when its first `FAIL <step>` line names `failingStep`. Scripts that print no `FAIL <step>` lines (mobile, modal, public-tools, landing, spacing, ui) must record `failingStep: null`, which matches only a failure with no FAIL line. `writing-timer-locked` keeps `YJS_ROOM_SESSION_TTL_SECONDS` at its default (`writing-timer-live-check.mjs:8-9`: B's clock runs 2 minutes ahead, so a 60 s session already looks expired when B reopens); `board-reactions-locked` and `room-lock` use 60 s. Entries are recorded by the baseline runs; a manifest change needs a reviewer note. `baselines.unitTests.atBaseline` is the unit count before P0 tasks 3-8 and `baselines.bundle` the `vite build` sizes (match by `prefix` and `ext`); later phases compare against the count re-recorded at the end of P0 (task 9 step 4), not `atBaseline`.
